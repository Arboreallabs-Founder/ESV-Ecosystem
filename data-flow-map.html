🔐 Three access paths to Postgres

  • SSR anon client (createClient) — every authenticated read/write; RLS enforced via get_user_role().
  • Service-role client (createAdminClient) — server-only, bypasses RLS; used for unauthenticated public form submission.
  • SECURITY DEFINER RPCs — validate server-side then bypass RLS for anon-safe operations.

🛡️ Guard pattern

  • Every mutating action calls requireAdmin() / requireInternal() / requireSuperAdmin() at the top.
  • Guards read JWT claims (getClaims) then look up users.role + org_id.
  • proxy.ts does a cheap getSession() check and role-based redirect; pages re-validate.

🏢 Multi-tenancy

  • organizations scopes all data; rows carry org_id.
  • Super Admin manages orgs & seeds users via approved_emails.
  • Login routing: super_admin→orgs, partner→portal, associate→pipelines, else→dashboard.

✍️ Write vs Read separation

  • All writes funnel through /src/app/actions/* (server actions only).
  • Page loads read through /src/lib/* fetchers.
  • No revalidatePath — clients call router.refresh() after mutations.

💰 Partner earnings

  • Deals link partners via referred investors on active_deal_investors.
  • Fee splits stored in active_deal_investor_fees + active_deal_partner_shares.
  • Aggregated by get_partner_earnings(p_partner_id) RPC for portal & admin views.

📋 Stage gating

  • pipeline_stage_questions define per-stage required answers.
  • Moving an entry records pipeline_entry_stage_history + _stage_answers.
  • Rejections store rejection_reason on the entry.
